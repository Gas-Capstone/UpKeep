# As a user, I can try to login and see security features
*Written by: pdinger0*
We added several new security features to help protect user accounts.

- Added two-factor authentication using an authenticator app
  - Users can set up 2FA from the Settings page
  - A QR code and manual setup key are generated for the user
  - The user enters the 6-digit code from their authenticator app to confirm setup
  - Once enabled, users are challenged for their authenticator code when signing in
- Added stronger password requirements
  - Passwords must be at least 10 characters long
  - Passwords must contain an uppercase letter
  - Passwords must contain a lowercase letter
  - Passwords must contain a number
  - Passwords must contain a special character
- Added password history
  - Users cannot reuse either of their two most recent passwords
  - Previous passwords are stored securely as password hashes
  - Password changes are handled through a Supabase Edge Function instead of directly from the client
- Users must provide their current password before changing to a new password

# As a developer, I would like CI/CD to help my testers and users get the latest updates easier
*Written by: tbraud03*

- I added CI/CD in the form of GitHub Workflows, EAS Workflows, and EAS Update.
- CI:
  - For every PR, a CI GitHub workflow runs, performing the following tests:
    - A linter checks for syntax and formatting errors
    - A typecheck ensures no type safety errors
    - A regression test is performed on the CardMenu and ScreenView components
      - These tests are implemented using Jest
      - These components were chosen because they are used widely across core pages of the app
        - CardMenu is used for Workouts and Meals
        - ScreenView is a layout component to help ensure a consistent layout across the app
  - If one of the CI tests fails, the PR is unable to be merged
- CD:
  - An EAS Workflow triggers on merge to dev/main
    - The workflow checks the app fingerprint, which is then used to determine if a new build needs to be made
      - A new build is made only for native-level changes, such as a config change or a new package
    - If a new build needs to be made, it submits a build request to EAS Build and builds in the cloud
      - If the build is for the dev branch, it makes a dev build. If the build is for the main branch, it makes a preview/production build.
    - If a new build isn't required, and the workflow is triggering off of a change to main, it submits an EAS Update
      - EAS Update allows our production builds to download changes over the air, meaning our sponsors/testers don't have to install a new build for every single change
- CI/CD helps us catch errors before they become big issues, and helps our sponsors/testers get the latest updates easier and quicker.


# As a user, I can interact with an AI agent that provides assistance according to my direction
*Written by: ZeRoCodesBZ*

- Added an assistant you can open from the robot icon on the home screen and talk to in plain language
- It doesn't just answer questions, it takes real actions in the app: adding a recipe's ingredients to your grocery list, moving your shopping into the fridge, creating habits, checking habits off, and telling you what you can cook right now
- When it isn't sure what you meant, it asks instead of guessing. "Add what I need for stir fry" gets answered with "Which stir fry did you mean?" and tappable options
- It understands follow-ups. "I bought those ingredients" and "add them to my fridge" work because recent conversation is sent along as context, so the assistant knows what "them" refers to
- The model runs on a self-hosted server rather than a paid API, so there's no per-message cost
- It's built to be safe to reach from the internet:
  - Every request carries the signed-in user's own login token, and the database's row-level security decides what the assistant is allowed to touch. It physically cannot read or change another user's data, even if it tried
  - The token is checked before the model is allowed to run, so a bad request is turned away cheaply instead of tying up the machine
  - The server is reachable through a Cloudflare tunnel, which means the assistant works anywhere, not only on our home wifi

- Every built-in recipe and workout plan now has a photo on its card, and recipes show a larger one at the top of the recipe page
- The photos live in storage buckets that are readable by anyone but writable by no one, so they can't be replaced or deleted through the app
- Users can also set their own photo on recipes and workout plans they created themselves, chosen from their photo library through the card's menu
  - Those uploads go into a folder named after the user, which is what the storage rules check, so one user can't overwrite another's pictures
