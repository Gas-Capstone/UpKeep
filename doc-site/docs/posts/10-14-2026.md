# Sprint 5

#### October 14, 2026

###### written by: tbraud03, pdinger0, KarkaVon, ZeRoCodesBZ

## Overview

October 13 marks the end of Sprint 5. In this sprint, we focused mainly on improving account security, notifications, and the Settings page. We added two-factor authentication, stronger password requirements, password history checks, and notifications that change based on the user's primary wellness goal.

## Account Security

We added several new security features to help protect user accounts.

- Added two-factor authentication using an authenticator app
  - Users can set up 2FA from the Settings page
  - A QR code and manual setup key are generated for the user
  - The user enters the 6-digit code from their authenticator app to confirm setup
  - Once enabled, users are challenged for their authenticator code when signing in
- Improved the 2FA setup process
  - If a user starts setting up 2FA but closes or reloads the app before verifying it, they are not locked out of setting it up again
  - Old unverified 2FA factors are removed before a new QR code is generated
- Added stronger password requirements
  - Passwords must be at least 10 characters long
  - Passwords must contain an uppercase letter
  - Passwords must contain a lowercase letter
  - Passwords must contain a number
  - Passwords must contain a special character
- Added password history
  - Users cannot reuse either of their two most recent passwords
  - Previous passwords are stored securely as password hashes
  - Password changes are handled through a Supabase Edge Function instead of directly from the client
- Users must provide their current password before changing to a new password

## Notification Improvements

Notifications were expanded to give users reminders that are more relevant to their selected wellness goal.

- Daily summary notifications can be enabled or disabled from Settings
- Users can choose what time they want their daily summary notification
- Added a button to send a test notification
- Notifications now use the user's primary goal to provide a more relevant message
  - Improve mobility users receive movement-related reminders
  - Build muscle users receive strength-related reminders
  - Build endurance users receive aerobic/cardio-related reminders
  - Manage weight users receive meal-planning related reminders
- Goal notifications are combined with the user's normal daily summary
- Changing a user's primary goal automatically updates which type of goal message they receive
- Habit reminders and meal reminders can also be enabled or disabled separately

## Settings Improvements

The Settings page received several changes to make account management easier.

- Added a full two-factor authentication setup section
- Added QR code display and manual authenticator setup key
- Added password security information to the password section
- Password errors now appear directly inside the password section instead of scrolling the user to the top of the page
- Password success messages also appear inside the password section
- The password section remains open after a successful password change so the user can see the confirmation
- Improved handling of status and error messages throughout Settings

## Backend and Database Changes

Several backend changes were added to support the new security features.

- Added a password history table
  - Stores the user's recent password hashes
  - Automatically removes older passwords so only the two most recent passwords need to be checked
- Added database functions for:
  - Checking whether a password was recently used
  - Recording a password in password history
- Restricted password history functions so they cannot be called directly by normal authenticated users
- Added a Supabase Edge Function for changing passwords
  - Verifies the user's current password
  - Checks password history
  - Records the old password
  - Updates the user's password securely
- Expanded use of Supabase MFA functions for enrollment, verification, factor checking, and cleanup

## Testing and Bug Fixes

A number of edge cases were tested during this sprint.

- Verified that incorrect 2FA codes are rejected
- Verified that users are challenged for 2FA during login
- Tested closing and reopening the app during an unfinished 2FA setup
- Tested generating a new QR code after abandoning a previous 2FA setup
- Verified that users cannot reuse either of their two previous passwords
- Verified password requirement errors
- Tested scheduled goal-based notifications
- Fixed password errors and confirmations causing the Settings page to scroll away from the password section
